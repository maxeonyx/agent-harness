# Experiment Brief: provider-cache-probe

Pulled from the `PLAN.md` targeted-questions pool. User-confirmed 2026-08-04 ("Yes, definitely. That is a great, well-scoped experiment.") and again 2026-09-08, with the providers and models named then: the Anthropic Messages API on `claude-sonnet-5` and the OpenAI Responses API on `gpt-5.6-luna`.

Thesis: the cache model the design already assumes is realisable on both APIs, and its whole cost model is three multipliers on the base input rate — 1.25× to write a prefix, 0.1× to read one, 1× for anything outside a prefix. Four assumptions carry the weight. **Nested prefixes**: a context has several cache points at once and the provider finds the longest one, so a fork boundary, a system section and a message-undo point can all be cache points simultaneously without the harness choosing between them (`REQUIREMENTS.md`, "A context has several cache prefixes at once, nested"). **Append-only warmth**: appending to the end of a context reuses everything before the append, so notices, piggybacked user activity and tool results cost only their own tokens. **Fork inheritance**: two sessions sharing a long prefix and diverging both read that prefix, which is the mechanism the forked-subagent design rests on — "That is why forked sub-agents work at all." **Cross-model reads**: a cheap utility model can read a prefix the main model wrote, which Max flagged as worth confirming empirically because it decides whether the change-classification utility model runs against the live context or against its own one-shot context.

Falsified if: the reported `usage` fields cannot be decomposed into those three multipliers, so cost is not predictable from a request before sending it; or append-only warmth does not hold, because a cache point must be *chosen* in advance and only the chosen one is reusable, which would make the nested-prefix claim a fiction and force the harness to predict its own future cache points; or a fork reads nothing from its parent, which would remove the economic basis for forking rather than compacting; or tool-set changes cannot be represented at all without discarding the prefix, in which case the "keep old tools working until cache expiry" ruling is not a policy choice but the only possibility; or the two APIs disagree so deeply that one context model cannot serve both, which would make the provider a design-shaping concern rather than an adapter.

Invariants touched: **2** — the trigger list includes "cache-nearly-expired handover", which needs cache age to be knowable, so whether TTL and expiry are observable at all is an invariant-2 question, not a detail. **5** — "cache-supporting-transient" is a named data class, and this experiment says what actually has to be stored to reproduce a prefix after a restart, which is the open tension between Max's two persistence entries in `REQUIREMENTS.md`. **8** — the probe is disposable evidence under `experiments/` and none of it is a candidate for core.

Prior knowledge is verified, not re-derived. The `PLAN.md` entry records what the Anthropic docs said on 2026-08-12; the probe re-reads both providers' current documentation, records the URL and read date in every run's summary, states each measurement's documented expectation alongside its measured result, and so shows agreement and disagreement in the same table. The OpenAI Responses API's caching behaviour was not recorded anywhere before this experiment.

Shape: one question per request pair. A measurement writes a prefix, mutates exactly one thing, sends the second request, and reads the answer out of the provider's own `usage` block — a nonzero cache-read count means the prefix survived the mutation. Every measurement seeds its filler text from the run id plus its own id, so no measurement can read a prefix another one happened to write, and no run can read the previous run's cache.

Cost: the probe prints an upper bound before sending anything. For the 36 default measurements that bound is **US$0.35** (US$0.30 Anthropic, US$0.05 OpenAI), assuming every request pays a full cache write over its entire body and burns its whole output budget; both are pessimistic, so the real figure should land near half of it. The two Anthropic TTL measurements and the OpenAI one are excluded unless `--slow` is passed, because they wait out a cache lifetime: they add roughly forty minutes of wall clock and a few cents.

Out of scope: streaming responses, since cache accounting arrives in the `message_start` usage block either way; the OpenAI `additional_tools` and deferred tool-search mechanisms, which are the documented append-only route for adding a tool mid-thread and deserve their own measurement once the basic tool answers are in hand; batch, flex and fast service tiers; 1-hour and 24-hour retention as a cost strategy; and any harness-side caching policy, which is the context-updates experiment's job.

Exit condition: for each provider, a measured answer to every question in the `PLAN.md` entry — what counts as a prefix and where breakpoints may go, write versus read versus uncached as actually reported, whether the previous assistant turn is charged as a write, TTL behaviour and its observability, which tool-array changes survive, what a fork inherits, whether a smaller model reads a larger model's prefix, and late system-section changes — with the raw request and response bodies kept beside the summary as evidence, and an outcome document written from `EXPERIMENT_OUTCOME_TEMPLATE.md`.
